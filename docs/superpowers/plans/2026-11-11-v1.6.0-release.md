# ti 1.6.0 Release Plan

**Goal:** Fix what the pre-release review found, check the build end to end,
and release 1.6.0: dependency bump plus `ti pomodoro`, on GitHub Releases
and crates.io.

**Architecture:** No new modules. Fixes go in `src/timer.rs` + `src/app.rs`
(phase overrun), `src/interface.rs` (testable drawing) and `src/main.rs`
(single subcommand match). The release follows 1.5.0: feature PR → release
PR (version + changelog) → `v1.6.0` tag (dist builds the GitHub Release) →
manual `cargo publish`.

**Spec:** the pomodoro decisions from the 2026-11-11 session (D1–D5) and the
review findings R1–R4 below.

## Decisions

| # | Decision |
|---|----------|
| D1 | `ti pomodoro`: 25 / 5 / 15 minutes, long break after every 4th work session; `--work`, `--break`, `--long-break`, `--rounds` override (each ≥ 1). |
| D2 | A finished phase rings the terminal bell and the next phase starts on its own. |
| D3 | A session resumes from its own cache (`ti_pomodoro.tmp`): phase, round, remaining seconds. `--clear` starts fresh. |
| D4 | The status line shows phase and round (`WORK 2/4`, `LONG BREAK`); breaks are green; `N` skips; `R` restarts the current phase. |
| D5 | Countdown options (`TIME`, `-H/-M/-S`) combined with `pomodoro` are a usage error (exit 2). |
| D6 | Version **1.6.0** (new feature, no breaking CLI change). |
| D7 | Repo-only files (`CLAUDE.md`, `docs/`) are excluded from the crates.io package. |

## Review findings

| # | Finding | Fix |
|---|---------|-----|
| R1 | When the loop is late, the time that ran past a phase's end isn't taken off the next phase (the next phase restarts at `now`). | Task 2 |
| R2 | `cargo package` ships `CLAUDE.md` (and would ship `docs/`). | Task 4 |
| R3 | Drawing (`draw_timer`) has no tests: it reads the real terminal size. `interface.rs` line coverage is 69.5%. | Task 3 |
| R4 | `main.rs` matches the subcommand twice with a placeholder `0`; the README key table is misaligned. | Task 4 |
| R5 | Found by Review Focus 2 in Task 2: pausing exactly when a pomodoro phase ends finished the timer inside `pause`, and `App::tick` never moved on, so the session sat at 00:00:00 for good. | Task 2 |

State at review: fmt, clippy (`--all-targets`), 75 unit + 11 CLI tests,
locked and release builds all pass; line coverage 92.6%.

## Global Constraints

- No new dependencies.
- No `unwrap`/`expect` in production code; tests may use them.
- Conventional Commits, one commit per task, on `feat/pomodoro`.
- Run the four gates from `CLAUDE.md` before every commit.
- Nothing is pushed, merged, tagged or published without the owner's go-ahead
  at that step (Tasks 7–10).

## Review Focus

1. **A loop that is late by more than a whole phase** (e.g. 3s late with a 1s
   break) must skip through every phase it missed and land on the right phase
   with the right time left. Pinned by `app::tests::late_tick_carries_overrun_across_phases`.
2. **Pausing exactly when a phase ends** must start the next phase paused or
   running, never stay at 0. Pinned by `app::tests::pause_on_phase_end_moves_on`.
3. **Status line in a terminal narrower than the text** is clipped, never
   wrapped. Pinned by `interface::tests::draw_clips_status_line`.
