# ti 1.7.0 Release Plan

**Goal:** Close every open issue (#22–#26), add a screen flash as a
visible fallback for the bell, and release **1.7.0**. Sleep behaviour gets
documented, the Linux gnu
binary moves to manylinux (glibc ≤ 2.28), Dependabot keeps pins fresh, and
the interactive screen gets automated pseudo-terminal tests.

**Architecture:** The only production change is the alert flash:
`src/app.rs` (when to alert, flash deadline) and `src/interface.rs` (draw in
reverse video). The rest: `README.md` (sleep behaviour),
`dist-workspace.toml` + generated `.github/workflows/release.yml` (gnu in
manylinux, both Linux jobs on `ubuntu-24.04`), new `.github/dependabot.yml`,
new `tests/screen.rs` with `portable-pty` as a dev-dependency (`Cargo.toml`,
`Cargo.lock`), and `CLAUDE.md` (testing notes). The release follows 1.6.2:
PR → merge → signed tag `v1.7.0` (dist builds the GitHub Release) → manual
`cargo publish`.

**Spec:** issues #22–#26, the owner's decisions from the 2026-11-18
session (D1–D6), and
[`2026-11-18-alert-flash-design.md`](../specs/2026-11-18-alert-flash-design.md)
(F1–F4).

## Global Constraints

- No new dependencies except `portable-pty` as a **dev**-dependency (D2).
- No `unwrap`/`expect` in production code; tests may use them.
- Conventional Commits, one commit per task, on `release/v1.7.0`.
- Run the four gates from `CLAUDE.md` before every commit.
- Each of these waits for the owner's go-ahead at that step: pushing, opening
  the PR, changing repo settings, merging, tagging and publishing.

## Review Focus

1. **A screen test must never hang `cargo test`.** Every read from the pty
   has a deadline, and the child is killed when the test ends, pass or fail.
   Pinned by `screen::countdown_finishes` (deadline helper) and checked by
   running `cargo test` in a real terminal.
2. **Tests running in parallel must not share a cache file.** Each test gets
   its own `--cache` path. Pinned by `screen::reset_deletes_cache` and
   `screen::pomodoro_resumes_seeded_cache` running together.
3. **Windows ConPTY** re-renders the output and turns input bytes into key
   events, so raw byte checks (bell, green) may not survive. Pinned by the
   Windows CI run of `screen::pomodoro_phase_end_rings_bell_and_turns_green`.
   If ConPTY can't support the tests, **stop and ask** before adding
   `cfg(unix)`, because D3 relies on Windows coverage.
4. **Alerts fire only on a transition.** A countdown that's already
   finished at start (`ti 0`) doesn't alert, `N` doesn't alert, and one
   late tick through several phases alerts once. Pinned by
   `app::tests::finished_at_start_does_not_alert`,
   `app::tests::skip_does_not_alert` and the existing
   `late_tick_carries_overrun_across_phases`.
5. **The flash ends by itself.** The loop must wake up at the flash
   deadline even when the timer is paused or finished, otherwise the screen
   stays inverted until the next key press. Pinned by
   `app::tests::flash_ends_after_a_second_while_paused` (`until_next_tick`
   returns the flash deadline and `tick` returns `Changed` at it).
6. **The gnu binary's glibc floor.** Checked on the PR run's artifact: the
   highest `GLIBC_` symbol from `objdump -T` is ≤ 2.28, and the binary runs
   (`ti --version`) in a glibc 2.28 container.

## Verification

**Task 1** (2026-11-18, Linux / Fedora 44, release binary in a Python pty,
`ti --clear -s 30`):
- `kill -STOP`, 5 s, `kill -CONT`: the cache went 29 → 22 over 6.5 s, so
  the stopped time counts (`CLOCK_MONOTONIC` keeps running while a process
  is stopped).
- `Ctrl+Z` (byte 0x1a): ignored; the timer kept running (29 → 22) and `ti`
  wasn't suspended.
- Not checked: real system sleep on any OS. Linux/macOS follow from the
  std clocks (`CLOCK_MONOTONIC`, `CLOCK_UPTIME_RAW`); for Windows,
  "counts sleep" follows from `QueryPerformanceCounter` and hasn't been
  checked on a machine.

`quay.io/pypa/manylinux_2_28_x86_64` (host musl); `release.yml` has no
